> 상태: PASS — 아래 implementation commit에 한정
> 실행일: 2026-07-31
> 시험 등급: T2 credential-free Windows installer smoke
> 사람 OAuth 및 실제 계정 사용량 증거: 없음

이 문서는 공식 `install.ps1`과 실제 Codex CLI를 GitHub-hosted Windows runner에서 시험한 개인정보 비포함 snapshot이다. T3 사람 OAuth 시험을 대신하지 않으며, 이 문서를 추가하는 후속 documentation commit을 포함해 release commit이 달라지면 같은 commit에서 T2를 다시 실행해야 한다.

## 확인한 계약

두 job 모두 다음을 확인했다.

- 공식 `https://chatgpt.com/codex/install.ps1` process exit `0`
- 실제 설치본의 `codex --version`, `login --help`, `app-server --help` exit `0`
- 빈 격리 `CODEX_HOME`에서 `login status` exit `1`, `authenticated=false`
- OAuth, API key, access token과 실제 계정 사용량 요청을 시도하지 않음
- repository live harness가 실제 설치본을 선택하고 version `0.146.0`을 확인
- 기본 위치 job은 `default_standalone_path`와 fresh HKCU PATH 등록을 확인
- custom job은 공백과 한글이 있는 위치에서 `custom_install_dir` 선택을 확인
- raw 명령 출력, credential, 전체 runner home·temporary path를 evidence JSON에 포함하지 않음

## 증명하지 않은 것

- Windows 11 desktop UI, SmartScreen 또는 RDP
- 사람이 수행한 ChatGPT browser OAuth, MFA와 workspace 선택
- API-key credential과 ChatGPT subscription credential의 사용량 차이
- 실제 `account/rateLimits/read`
- 앱 재시작, Windows 재부팅, legacy npm 충돌과 앱 제거 뒤 credential 보존
- Node.js, npm과 Rust가 모두 없는 pristine 고객 PC
- Authenticode publisher 또는 공식 binary hash manifest

따라서 이 결과만으로 “로그인 전체 흐름 통과”, “고객 PC 전체 검증 완료” 또는 “공개 Release 준비 완료”라고 표현하면 안 된다.

## 같은 시점의 standard CI 상태

[Standard CI run 30567446378](https://github.com/Kyuhan1230/ai-usage-monitor/actions/runs/30567446378)은 implementation commit에서 test와 NSIS build까지 진행했지만, silent install 뒤 설치된 앱과 비교 대상으로 지정한 build output의 byte hash가 다르다는 assertion에서 실패했다. 설치 process 자체는 exit `0`이었고 finally uninstall이 실행됐다.

이 failure의 원인이 해결되고 후속 commit의 전체 standard CI와 같은-commit T2가 모두 성공하기 전까지 최종 자동 gate는 **pending/No-Go**다.
